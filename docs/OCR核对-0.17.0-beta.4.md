# OCR 核对与批量确认（0.17.0-beta.4）

## 问题与修复

旧版确认按钮依赖应用内原图缓存；任意页的预览请求还与全部保存/确认按钮共用 busy 状态，未返回就会锁住整个核对区。禁用按钮的 wait 光标也会让静态禁用状态看起来像持续加载。合成页面已重现这一行为；用户补充最后尝试的是第3页人工核对按钮。

新版将 PDF.js 原图渲染移至前端 worker，各页有独立加载状态、取消与30秒超时，清理不阻塞按钮恢复。人工确认不再依赖图片缓存，可对照外部原PDF；已识别待核对页可跨文件勾选、全选并批量通过，未识别页不能选，有未保存校订的选择会阻止通过。

保存使用独立 IPC：读取最新课件、检查所有选中页状态与原文快照，再一次持久化。单页校订仅清除本页已保存草稿，保留其他页草稿与原始转录。切换课件时取消尚未结束的预览。

## 验证范围

- 自动化覆盖原图读取超时、取消、渲染与清理无响应、迟到结果、跨文件批量核对、未识别页、过期页面、原始转录保留。
- 英语、语文、化学分别验证16页、每页36段材料确认后保存重载。
- 合成界面验证了单页预览挂起与取消、跨页草稿保留、未保存校订阻止批量通过、保存失败后保留选择与重试、跨试卷和答案的一次批量保存，以及未加载应用内原图时的人工确认。
- 原图渲染用内联合成 PDF 验证成功。测试浏览器读取本地 HTTP PDF 时返回204空响应，而主机同址读取为200及完整字节，因此该传输层结果不作为桌面 IPC 预览失败的证据。
- 浏览器与打包桌面验证使用合成 PDF，不读取用户真实课件，不调用云端 API。
- 安装升级与用户截图中的实际 PDF 尚未端到端复测。
