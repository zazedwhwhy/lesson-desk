## 3. 逐项分析（原 O01 已整改，O02–O07 为当前待改项）

### O01（已整改，对应当前 R36）：无法识别的接口错误默认成“本项材料错误”

**当前状态：已整改，静态复核通过，不计入当前 6 类过度防御。** 错误响应解析失败直接抛 ServiceStopError；只有 context_length_exceeded / max_tokens_exceeded / too_many_tokens / request_too_large 白名单允许按材料错误继续，其余未知代码停止。以下保留整改前的因果分析与源码，便于追踪整改依据。主代理新增了对应聚焦测试，本审计代理没有运行它们，不据此声明测试通过。

- **名称与位置**：`src/desktop/ai.ts:38`，调用链为 `callAI → 各生成器 → 调度器`。优先级：高。
- **触发条件**：服务返回 400 / 413 / 422；错误体不是 JSON，或者 JSON 不含已列出的少量全局错误码和 `param: model`。
- **当前回退模式**：JSON 解析任意异常被转成 `detail=null`，随后默认抛 `GenerationContentError`，告知“其他任务继续”。即使正常 JSON 返回未知错误码，也执行同样的默认分支。
- **问题与负面影响**：未知错误可能是地址路由、接口协议、所有请求共有的不支持参数、服务鉴权策略等全局问题。没有足够证据将其认定为“仅此材料有错”。原响应被丢掉后，后续任务可能重复失败；英语解析还可能进入 O02 的额外“修正”请求。401 / 403 等直接暂停路径不受此问题影响。
- **改造方案**：未知、无法解析或无法识别的接口拒绝默认抛 `ServiceStopError`，提示“接口拒绝请求（HTTP {status}），错误类型未确认，后续任务已暂停；请检查地址、模型和接口参数。”仅对白名单内容错误（如服务明确返回上下文超长）抛 `GenerationContentError`。把有界、去除密钥及敏感材料的响应摘要保存到诊断信息；扩展 `ServiceStopError(message, {cause})` 保留原异常。不能把全部 400 简单一律认定为凭据错误，也不能继续默认认定为材料错误。

### O02：英语解析把未知异常转成可由模型修复的失败

- **名称与位置**：`src/desktop/ai.ts:91–95`；`src/desktop/generation-service.ts:20–29`。优先级：高。作为同一条“解析失败 → 状态默认 → 单题修正”策略合并计 1 类。
- **触发条件**：批解析或逐题绑定中出现任意非取消、非 `ServiceStopError` 的异常，例如无效返回值、意外的 `TypeError`、内部版本/任务对象不一致；也包含正常的 AI 漏题、证据不合法等内容错误。
- **当前回退模式**：宽泛 catch 把异常缩成 `t.error` 字符串，设置 failed；外层枚举 failed 题目，无差别显示“校验失败，AI正在单题修正（1/1）”并再次请求。
- **问题与负面影响**：已知内容问题的单题修正有意义，但程序不变量破坏或服务协议失败不能靠重新生成答案修复。当前行为将其改名为“校验失败”，丢失异常类型、原始堆栈，并增加请求成本。`generateGroup` 使用部分类型断言和非空断言，因此不是只有预期校验错误能到达这些 catch。
- **改造方案**：将漏题、字段、证据、答案不一致统一包装为 `GenerationContentError` / 子类 `AnalysisContentError`，仅这种异常进入单题修正。出现未知异常时记录任务 ID 后直接抛 `GenerationInvariantError`（建议新增），提示“解析内部状态异常，后续任务已停止，已保存结果保留；请查看诊断编号 {id}”。保留 `{cause:error}`。必须同步修 O03 的上层策略，否则只在本层 rethrow 仍会被当作单项失败继续。

### O03：英语通用调度器仅对一种错误停止

- **名称与位置**：`src/core/generation.ts:62`。优先级：高。
- **触发条件**：`execute()` 抛出取消和 `ServiceStopError` 以外的任何错误，包括某个生成器不再属于可修复内容失败的程序错误、响应协议错误等。
- **当前回退模式**：把当前任务写成 failed，默认继续下一任务，仅 `ServiceStopError` 设置 stopReason 并 break。
- **问题与负面影响**：任务独立性不能证明未知异常仅影响当前任务。共享数据/执行器出现系统性问题时，继续执行会重复消耗请求，还把整个任务以普通 partial/failed 返回。这里**不是完全静默**：错误会写入逐项状态；缺陷是错误语义被压平，停止策略过宽。`checkpoint()` 在正常路径位于 catch 外，不能据此声称所有保存错误也被此 catch 吞掉。
- **改造方案**：显式允许 `GenerationContentError` / `TaskInputError`（建议新增）作为本项失败继续；其它错误保留 cause，设置 `stopReason` 并停止执行，向调用者抛 `GenerationRunError` / 原始异常。提示“生成发生非内容错误，已停止后续任务；完成项已保留。”错误结构应同时保留 `name`、任务 ID 和内部诊断堆栈，UI 可继续只显示友好消息。已知无完整句子等当前使用普通 Error 的预期校验，需要先改成明确类型，不能直接把所有普通 Error 继续当内容错误。

## 4. 合理防御点的保留理由

- **R01–R04：首次使用与缺省资源。** 仅 ENOENT 使用初始设置、空错题本、内置提示词/模板；JSON 损坏、权限错误等会继续抛出。没有把“读取失败”统统解释成“第一次启动”。提示词未覆盖时使用原始指令也是明确的产品默认，而不是模型失败后的假答案。
- **R05–R07：队列与资源释放。** NotebookStore 的 `this.queue=task.catch(()=>{})` 只恢复内部调度链，返回给调用者的仍是原 task；不会把保存失败变成功。备份只忽略已存在/原文件尚不存在；事务清理后继续抛错，PDF 和临时窗口用 finally 释放。保留这些机制。清理动作自身失败可能替换原异常，可将原错和清理错一并记录，但它仍会失败退出，不属于静默降级。
- **R08–R09：可观察的损坏和中断。** 课件列表保留出错目录的错误卡片，不写坏课件、不伪装空列表；读取列表使用 `load(...,false)` 避免恢复操作。重新打开后将旧 running 转 pending/interrupted，准确承认进程已中断，没有将任务改为 complete。
- **R10–R13：服务安全闭包。** 密钥、模型、地址校验失败立即停止；网络错误/超时不自动再发可能已计费的请求；429/5xx 有最多两次、可取消的退避重试。输出空值、拒绝、截断、无效 JSON/schema 不会用通用文本代替，直接拒绝保存。JSON 围栏兼容仍要解析并验证真实返回值，不是伪造内容。原 O01 的错误 HTTP 响应未知分类已修复为 R36，不应误删其它保护。
- **R14–R16：有限修正与结果保留。** 教学模块和独立练习只为明确内容错误尝试一次修正，不为 ServiceStopError/取消/其它未知异常自动重试。取消和文件对话框取消是可预期用户操作，完成项保留，未完成项不假称完成。自动修正后的再次校对失败写入独立 recheck 状态并提示，保存修改与“校对成功”没有混为一谈。
- **R17–R20：界面边界与通知。** 浏览器示例标注“内容已预置，不代表 AI 已连接”，桌面 API 缺失时拒绝文件/AI 功能；不是桌面服务失败后切演示。系统通知失败不影响已经落盘的生成结果，并有应用内消息。UI 最外层捕获后展示错误、退出 busy 属合理交互隔离；没有返回伪造业务对象。语文预览保留 deckError、空 deck 禁止输出，是英语 O05 应参考的做法。UI 捕获的合理性不为 O02–O04 的后台未知异常继续执行背书。
- **R21–R22：可选值与草稿。** 空标签、尚未选择的 ID、无历史版本、可选的图片/词性/草稿/集合都不必让页面崩溃。生成数量的 0 明确表示“自动”，有 schema 范围约束。新建语文/化学数据和空教学骨架属于尚未生成的草稿；confirmed/studentReady 默认 false、completedModules 明确标识生成范围，不是 AI 失败后填模板并报成功。O06 已单独排除“有声明关联却失联”这一关键数据场景。
- **R23–R25：旧数据与同源复用。** 旧版完整教学包没有 completedModules 时按历史格式兼容，UI 有旧版说明；旧练习仍可查看并有格式提示，不是失败时新编的假题。有效练习/蓝图只在来源条件满足时复用；无蓝图会明确调用 AI 提炼，无可选新主题就报错。归档任务只是任务查询来源的替代，续跑还检查源指纹和核对状态。后续可强化旧版本迁移的完整性校验，但本轮未据此推断历史文件都缺模块。
- **R26–R27：证据保真。** 标点/空白归一最终返回真实原文连续子串；来源缺失、不匹配或规范化后多处匹配会报错。别名映射不存在时保留原 ID，不是随意改绑其它 ID，后续仍检查合法性。专项引用未提供具体段号时只在其声明的同一 source_id 全文查找，提供了错误段号反而直接拒绝；不按时间戳或猜测匹配新来源。校对引用异常包装为消息时可补 cause 保留堆栈，但当前仍中断，没有默认成功报告。
- **R28–R30：明确保留不确定性。** 专项证据不足/漏项/无参考答案转 needs_review；语文无参考答案时的解析建议保留待核实，图片未核验的校对强制 partial。化学非 ok 结果保留未确认版本、对应任务 failed，课堂/PPT 还要求 chemReady；status=ok 的教师和 AI 演练统一要求题目、答案、解析与迁移三块，避免教师另存待核实内容后绕过演练分离。保存“待核实草稿”不等于注入伪造成功数据。
- **R35–R36：未知错误停止。** R36 已将未知 HTTP 请求拒绝默认设为 ServiceStopError，只有明确材料错误白名单继续。 化学生成只允许 GenerationContentError / ZodError 这类明确内容失败继续，取消、ServiceStopError 和未知异常会 break。当前任务保留 failed/message，后续任务仍 pending，未返回假完成；成功结果持久化在 catch 外，存储错误直接抛出。虽然还可补充结构化 cause 和更明确的暂停汇总，但已经满足遇到未知错误阻断执行的要求。
- **R31–R32：导入与能力适配。** PDF 文字不足标记待 OCR，并阻止未 OCR 的整理；Word 图片占位文字明确提示对照补全。OCR 仅接受明确支持图片的模型，失败不会暗中切换服务。版面双栏估算有提示，不被当作排版准确性的保证。
- **R33–R34：外围排版。** 自定义 PPT 核心资源缺失会报错；可选字体、主题色和缺省占位框使用可读、安全边界内的显示值，不会生成课程事实。分页重排在候选失败时保留已知可行的原分页，未截断正文。此类呈现适配不应改为遇到缺省字体就中断业务。

## 5. 改造顺序与验收建议

1. **先明确错误类型，再收紧 continue/retry。** 处理仍待改的 O02–O04，并保留 R35、R36 的已整改策略：把 AI 内容、任务输入、服务配置/协议、程序不变量分开，只有预期内容错误允许当前项失败后继续。异常原因保存在内部诊断中，用户消息包含模块/题号和是否暂停。
2. **阻断错误数据变成“已核对”。** 优先处理 O06、O07：已声明外键必须完整解析，来源不能靠全文复制猜绑；合法无材料题保留支持。
3. **把真实构建原因展示出来。** 处理 O05，构建成功状态与构建结果保持一致。

建议后续实施时的聚焦验收（**本轮未执行**）：

- 模拟 400 非 JSON、400 未知参数错误：后续任务不再请求；明确上下文超长则只失败当前内容项。
- 给英语、语文生成执行器注入 TypeError，并保留化学现有停止策略：后续任务暂停、已保存结果保留、诊断保留 cause；给明确内容验证异常则仍可按设计有界修正/继续。
- analysis 选中但没有选题：编排页显示真实阻断原因，不显示“可以放映和导出”。
- 导入外键失联但 confirmed=true 的英语/语文课件：对应错题不可自动成为 reviewed 条目。
- 多个空听力篇目、一个包含 Text 1 的答案源：不得把同一整段稿自动复制给多个篇目；教师完成显式关联后再恢复生成。
- 保留现有凭据阻断、有限重试、旧格式查看、取消恢复、逐项保存和非 ok 内容待核实等成功路径。
